Infosys Springboard · Team 03 (team lead)

Real Estate Due Diligence

A platform that turns an Indian property address into a six-category risk report, with an AI assistant and PDF/Excel exports.

View the codeLive site

Frontend online · backend currently offline

The problem

Buying property in India means checking flood maps, zoning rules, tax history and legal disputes across many portals. The platform pulls that together: add a property, and it produces a report with six scored risk categories, a plain-language verdict and downloadable PDF and Excel versions.

My role

This was a team project in the Infosys Springboard virtual internship, and I was the team lead. My own work was the backend architecture, Spring Security / JWT authentication, the service-aggregation pipeline, the six-category risk scoring engine and the deployment setup. Teammates built other features across the backend and frontend; they’re credited below and in the repository.

Architecture

A Next.js frontend talks to Spring Boot controllers. Services call the data sources, an aggregation layer assembles the property’s context, and the risk engine scores it. Report generation and the AI assistant work from that same context, and PostgreSQL stores users, properties, reports and history.

The AI assistant

The assistant streams answers from Llama 3.3 70B through Groq. Before each conversation the backend builds the system prompt from that property’s record: address, type, area, market value, zoning, condition and which fields are missing. Answers stay tied to the property the user is looking at, and off-topic questions are redirected. Report summaries use the same integration.

Getting access control right

Reports belong to the person who generated them. A report id in a URL isn’t permission, so the PDF, Excel and preview exports all run the same owner-or-admin check as viewing the report. Generating a report runs asynchronously in the background and notifies the owner in the app and by email when it’s ready.

Later improvements

Later, the codebase got two notable fixes. Notification preferences are now created race-free, and the report email is sent only after the report is committed; this is tested against a real PostgreSQL database. Property snapshot exports also now fail cleanly instead of returning placeholder data.

Where it stands

The frontend is live on Vercel; the AWS backend is currently offline, so the live site can’t generate reports. The repository has the full local setup and the backend test suite.
