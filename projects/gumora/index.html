Gumora

A marketplace where creators sell digital products through Cashfree checkout and buyers download from a personal library.

View the codeLive site

Storefront online at gumora.shop · API currently offline

What it is

Gumora is a Gumroad-style marketplace. Creators publish digital products, can import a listing’s description and images from an existing page, and get paid through Cashfree. Buyers see their purchases in a library and download the files from there.

It’s a decoupled app: a Next.js client and an Express/TypeScript API on MongoDB, with Redis caching for the public catalogue.

The hard part: knowing an order is paid

After checkout, Cashfree sends the buyer back to the site. That redirect is only a hint. The buyer might refresh it, open it in two tabs, or never come back at all. If “paid” were decided in the browser, or if marking the order and counting the sale were two separate writes, a retry could count one sale twice, or a crash could leave an order paid with no sale recorded.

How settlement works

The API asks Cashfree for the order and accepts it only if the order id, status, currency and amount (compared in paise, not floats) all match. Then, inside one MongoDB transaction, it moves the order from pending to paid and increments the product’s sales count.

The update only matches an order that is still pending, so a second confirmation sees an already-paid order and returns without touching the count. If the database can’t run transactions (a standalone MongoDB server), settlement refuses to run rather than falling back to two unsafe writes.

Other pieces worth a look

Product import fetches images through a guarded fetcher that only reaches public addresses, re-checks every redirect and caps the download size, so a creator can’t point the server at internal services.

The browser tests run against a production build with every API call mocked, so the CI pipeline can check sign-in, the catalogue and route protection without real payments.

Testing

Settlement is tested against a real MongoDB replica set started by the test suite, including concurrent confirmations of the same order, rolled-back transactions and injected server failures. A separate suite checks that a standalone server is refused.

Where it stands

The storefront at gumora.shop is online, but the API host is currently suspended, so sign-in and checkout don’t work on the live site; the full flow runs locally with a replica-set MongoDB.

Two improvements are written but not yet on the main branch: a signature-verified Cashfree webhook with a reconciliation sweep (for buyers who never return), and moving the session token fully out of browser JavaScript. The main branch still exposes a token endpoint that those changes remove.
