The problem

Entity resolution links noisy records that refer to the same business across different sources. Candidate generation must retain useful matches without making expensive pairwise comparison unbounded. Evaluation must also match the real scoring rule: a generic classifier accuracy number can hide harmful false-positive links.

My contribution and team context

The repository credits me with systems, harness and retrieval work and the ein track within Team Duty_Drive. This was a team submission, not an individual ranking. The team README retains contributor attribution. This portfolio avoids republishing teammate screenshots or private registration information and does not imply that I alone developed every modeling component.

Two different reproducibility surfaces

The default branch supplies the general harness: fold contracts, general metrics, experiment registration, unit tests and a synthetic end-to-end pipeline. Specialized entity-resolution code lives on dedicated competition branches. Full cloud inference depended on non-redistributable tournament data and cloud execution. Running the public synthetic pipeline therefore does not reproduce the competition score.

Why metric design matters

The specialized entity-resolution metric is entity-level macro F0.5. Its false-positive coefficient is four times its false-negative coefficient, so abstention and precision deserve explicit treatment. The default branch's general metric library should not be mistaken for that specialized metric. The README links the exact competition-branch implementation rather than pretending the complete system is on main.

Architecture and operational tradeoffs

The documented competition design moves through normalization, multi-lane candidate blocking, early pruning, richer features and reranking, then conflict resolution. Country-partitioned shards bound cloud execution. This is useful evidence of experiment and inference engineering, but the portfolio makes no unverified peak-memory or speed claim and does not treat the synthetic baseline as a benchmark of the specialized retriever.

How it is checked

The public README records 18 core-harness tests and a synthetic smoke workflow. A separate competition-branch suite covers the specialized metric and entity-resolution contracts. These scopes remain separate. The recorded team result is displayed public leaderboard rank #1,200 and score 0.978758. Its Unstop result page is not publicly linkable; the account-owned repository reports the result and private evidence can be shown on request.

Limits of the result

There is no verified participant denominator, percentile, prize or final private-leaderboard position on this page. The rank and score are the previously verified displayed public result, now documented in the repository; they were not reauthenticated on Unstop during this portfolio review. The public code demonstrates harness contracts and synthetic reproducibility, not a turnkey rerun of the cloud competition submission.
